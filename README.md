# Think Before AI

대학생의 생성형 AI 활용 과제에서 최초 사고, 힌트 이후의 재구성, 모범 답변 비교, 새로운 문제에 대한 독립 수행을 기록하는 한국어 교육용 웹앱입니다. HTML, CSS, JavaScript로 구성되어 있으며 별도 설치, 로그인, AI API, 서버 코드, 데이터베이스 없이 실행됩니다.

## 실행과 GitHub Pages 배포

- 로컬에서는 프로젝트 루트의 `index.html`을 브라우저에서 엽니다.
- GitHub Pages에서는 `index.html`, `styles.css`, `assignment.js`, `app.js`, `.nojekyll`, `README.md`를 저장소 루트에 올립니다.
- 저장소의 **Settings → Pages**에서 **Deploy from a branch**를 선택하고 배포할 브랜치와 **/ (root)**를 지정합니다. Pages 화면에 표시된 주소를 사용하세요.
- 앱 파일은 상대 경로로 불러오므로 사용자 사이트 루트와 저장소 이름 아래의 프로젝트 사이트에서 같은 파일을 사용할 수 있습니다. `.nojekyll`은 Jekyll 처리를 건너뜁니다.

## 학생용

1. 임의 식별코드와 최초 생각, 판단 근거, 해결 전략을 제출하면 힌트가 열립니다.
2. 수정한 생각과 변경하거나 유지한 이유를 제출하면 모범 답변이 열립니다.
3. 자신의 답변과 모범 답변을 비교해 차이점과 한계를 적습니다.
4. 새 독립 수행 문제에 직접 답합니다. 이 단계의 화면에는 앞선 힌트와 모범 답변이 표시되지 않습니다.
5. 완료 화면에서 JSON 파일을 내려받아 교수자에게 전달합니다. 첫 단계 제출 뒤에는 현재까지 제출한 기록만 담긴 JSON도 내려받을 수 있습니다. 각 제출에는 원문과 제출 시각이 기록되며 앱에서 다시 편집할 수 없습니다. 작성 중이나 다운로드 전에 새로고침하거나 탭을 닫으면 현재 세션의 기록이 사라집니다.

## 교수자용

학생 JSON을 불러온 뒤 **전체 문제와 제출 기록**을 펼치면 문제, 힌트, 모범 답변과 단계별 원문을 확인할 수 있습니다. 각 평가 영역에서 4수준 기술문과 관련 원문을 함께 확인하고, 수준을 선택한 뒤 평가 근거 메모와 종합 피드백을 작성합니다.

| 평가 영역 | 배점 | 연결되는 주요 기록 |
| --- | ---: | --- |
| 개념 이해 | 25 | 최초 답변, 최종 설명(힌트 후 수정 또는 유지), 독립 수행 답변 |
| 논리적 추론 | 20 | 최초 주장, 판단 근거, 해결 전략 |
| 비판적 판단 | 20 | 힌트 후 수정 또는 유지한 내용과 이유, 모범 답변 비교 |
| 독립적 문제해결 | 35 | 새 문제에 대한 힌트 없는 독립 수행 답변 |

영역 점수는 배점 × 선택 수준 ÷ 4로 계산하며 화면과 CSV에서는 소수점 둘째 자리까지 표시합니다. 모든 영역에서 1~4수준을 선택하면 최종 총점(100점 만점)이 확정됩니다.

- **미제출**은 해당 영역에 연결된 단계 기록 중 일부 또는 전부가 없는 상태입니다. 수준 선택을 잠급니다.
- **평가 불가**는 기록이 있지만 교수자가 평가에 사용할 수 없다고 판단한 상태입니다. 수준 대신 이 상태를 선택하고 사유를 메모에 남길 수 있습니다. 유효하지 않은 파일도 불러오기 단계에서 평가 불가로 표시됩니다.
- **미평가**는 필요한 기록이 있고 교수자가 아직 수준을 선택하지 않은 상태입니다.

위 세 상태는 합계에서 제외됩니다. 평가 중에도 JSON, CSV 및 인쇄용 화면을 사용할 수 있으며, 출력에 최종 총점의 미확정 상태가 표시됩니다. 학생 답변의 글자 수, 입력 시간, 특정 키워드 또는 AI 활용량으로 수준을 정하지 않습니다. 타당한 이유로 최초 판단을 유지한 학생도 높은 수준을 받을 수 있습니다. 이 평가 영역과 배점은 프로젝트용 초안이며 타당화된 척도가 아닙니다.

## 예시 과제 변경

`assignment.js`에서 과제 식별자와 제목(`id`, `title`), 최초 문제(`problem`), 힌트(`hint`), 모범 답변(`model`), 독립 수행 제목과 문제(`independentTitle`, `independent`)를 수정합니다. 과제 내용이 바뀌면 `id`도 변경하고 `app.js`의 루브릭 기술문이 새 과제에 맞는지 확인하세요. 기존 제출을 평가할 때는 해당 과제 버전의 앱을 사용합니다.

학생 제출 JSON은 기존 스키마 v1을 사용합니다. 각 단계의 필드명과 제출 시각을 그대로 읽습니다. 최종 설명은 기존 힌트 후 수정 내용(`revision`)을 사용합니다. 중간 다운로드 파일은 완료한 단계만 순서대로 담습니다. 구조 검사를 통과한 1~4단계 파일을 불러올 수 있습니다.

평가 JSON v2에는 영역별 상태, 수준, 기술문, 점수, 근거 메모와 함께 소계, 최종 확정 여부 및 종합 피드백을 저장합니다. 미확정 최종 총점 및 미채점 영역 점수는 JSON에서 `null`이고 CSV에서 빈칸입니다. CSV는 영역별 한 행을 출력합니다. 이전 평가 파일은 교내 보관용 결과이며 앱에서는 학생 제출 JSON만 불러옵니다.

## 데이터와 단계 잠금

학생 데이터와 교수자 피드백은 현재 브라우저에서 처리하며 서버로 전송하지 않습니다. 실명 대신 4~32자의 영문, 숫자, 하이픈 또는 밑줄로 된 임의 식별코드를 사용합니다. 사용자 입력은 HTML로 삽입하지 않고 텍스트로 표시합니다. 가져오기 파일의 크기(최대 1 MiB), JSON 문법, 스키마 버전, 과제 식별자, 단계 구조, 제출 시각, 필수 입력을 검사합니다.

단계 잠금은 학습 절차 유도 기능이며 보안 기능이 아닙니다. 정적 앱은 힌트와 모범 답변을 브라우저에 전달하므로 개발자 도구나 소스 파일로 내용을 볼 수 있습니다. 다운로드한 JSON도 외부에서 수정할 수 있으므로 앱의 잠금과 구조 검사는 제출의 진위를 보증하지 않습니다. 독립 수행 중 외부 AI 사용은 기술적으로 차단할 수 없습니다.

## 검증 결과

기존 배포본은 사전 사고의 논리성(20), 사고 수정과 재구성(25), 비판적 검토(15), 독립적 문제해결(40)의 4수준을 사용했습니다. 교수자 선택 수준을 배점에 곱한 뒤 4로 나누고 네 점수를 더했습니다. 학생 JSON v1은 과제 ID, 임의 식별코드, 네 단계의 제출 시각과 원문을 담았습니다.

변경본은 로컬 HTTP 서버의 `/think-before-ai/` 경로에서 헤드리스 Chrome으로 검증했습니다. 데스크톱(1262 CSS px)과 좁은 화면(504 CSS px)에서 아래 항목을 확인했습니다.

| 검사 | 결과 |
| --- | --- |
| 학생 4단계 | 식별코드와 공백 입력 검증, 단계별 힌트·모범 답변 공개, 독립 수행 시 힌트·모범 답변 숨김, 이전 입력란 제거와 완료 표시 |
| 학생 JSON | 기존 v1 구조로 내보내기, 기존 형식의 4단계 파일과 앞 단계만 제출한 파일 불러오기, 원문 보존 및 안전한 텍스트 표시, 잘못된 문법·구조 또는 1 MiB 초과 파일 거부 |

변경 파일은 `app.js`(루브릭·증거·점수·내보내기), `styles.css`(반응형 평가 배치), `index.html`(불러오기 초기 상태), `README.md`(사용·검증 문서)입니다. 실제 프린터 출력과 변경본의 공개 배포는 이번 검증 범위에 포함하지 않았습니다. 입력과 평가 기록은 현재 탭에 있으며 보관하려면 파일을 내려받아야 합니다.
